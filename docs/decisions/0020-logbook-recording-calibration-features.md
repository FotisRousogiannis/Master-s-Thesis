# ADR-0020: Ημερολόγιο σε SQLite, καταγραφή (REC) και calibration ανά άρθρωση ως λειτουργίες του UI

- **Κατάσταση:** Αποδεκτή
- **Ημερομηνία:** 2026-11-09

## Πλαίσιο
Από τη συζήτηση για την αρχικοποίηση (ADR-0019) προέκυψαν τρεις ανάγκες:
1. **Ποια στροφή στην εκκίνηση.** Μετά από επανεκκίνηση του ESP32 χάνεται ο μετρητής στροφών. Οι joint_1/4/6
   (±180°) μπορεί να διαβαστούν από τη λάθος πλευρά (181° → −179°). Ο Φώτης δεν θέλει να βασιστεί μόνο στο
   μηχανικό τερματικό.
2. **Calibration χωρίς κίνηση με το χέρι.** Ο βραχίονας δεν κινείται ελεύθερα με το χέρι (μειωτήρες των servo),
   άρα οι αρθρώσεις πρέπει να φέρνονται στη γωνία αναφοράς από το UI, μία-μία.
3. **Καταγραφή των κινήσεων.** Ούτε το ROS 2 ούτε το Gazebo κρατούν αυτόματα όσα περνούν από τα topics. Για τις
   μετρήσεις της διπλωματικής χρειάζεται καταγραφή και κατάλογος καταγραφών.

## Εναλλακτικές
### Πού κρατάμε τιμές (τελευταία θέση, ιστορικό)
| Επιλογή | Υπέρ | Κατά |
|---|---|---|
| Αρχείο YAML/JSON | απλό | μπορεί να μείνει μισογραμμένο σε διακοπή ρεύματος· δύσκολες αναζητήσεις |
| **SQLite** | ένα αρχείο, χωρίς server, έρχεται με την Python, transactions (όλα ή τίποτα), SQL | ένα σχήμα πινάκων για συντήρηση |
| PostgreSQL | ισχυρή | server και επιπλέον container για έναν υπολογιστή και έναν βραχίονα |
| NoSQL (MongoDB, Redis, TinyDB) | ευέλικτη μορφή | τα δεδομένα μας είναι δομημένα· server (MongoDB), κυρίως μνήμη (Redis), χωρίς transactions (TinyDB) |
| Flash του ESP32 (NVS) | δουλεύει χωρίς υπολογιστή | δύσκολη αποσφαλμάτωση, φθορά από εγγραφές, δεν φαίνεται από τον υπολογιστή |

### Mode ή λειτουργία
Τα modes (IDLE / MANUAL / AUTO / FAULT / STOP, ADR-0016) αποκλείουν το ένα το άλλο. Η καταγραφή χρειάζεται
**ταυτόχρονα** με MANUAL ή AUTO, και η μνήμη θέσης δεν πρέπει ποτέ να είναι κλειστή.

## Απόφαση
### 1. Ημερολόγιο: SQLite, package `arm_logbook`
- Ένα αρχείο: `$ARM_DATA_DIR/arm_logbook.db` (στο Docker `<repo>/.local/`: στον δίσκο του υπολογιστή, εκτός git).
- Το node **`/arm_logbook`** είναι το **μόνο** πρόγραμμα που ανοίγει τη βάση. Οι άλλοι γράφουν με γεγονότα στο
  `/logbook/event` (`std_msgs/String` με JSON· γίνεται τυποποιημένο μήνυμα όταν υπάρξει το `arm_interfaces`).
- Κάθε εγγραφή είναι ένα transaction με `synchronous = FULL`· έκδοση σχήματος στο `PRAGMA user_version`.

| Πίνακας | Περιεχόμενο | Γράφεται |
|---|---|---|
| `last_position` | θέση κάθε άρθρωσης (με τις στροφές) και ώρα | αυτόματα, όταν ο βραχίονας σταματά σε νέα θέση (ακίνητος 0.5 s) |
| `calibrations` | άρθρωση, νέο μηδέν, γωνία αναφοράς, φορά, ώρα | σε κάθε ορισμό μηδενικού |
| `recordings` | έναρξη, λήξη, φάκελος, σημείωση, topics | με το «● REC» |
| `faults` | πηγή, μήνυμα, λεπτομέρειες, ώρα | από το υλικό (π.χ. άλμα encoder, ADR-0019) |

Το `calibration.yaml` **μένει η πηγή αλήθειας στο git** (ADR-0017)· η βάση κρατά το αναλυτικό ιστορικό.

### 2. Τελευταία θέση: πάντα ενεργή, μόνο για τον πραγματικό βραχίονα
- Γράφεται μόνο με `hardware:=real` (παράμετρος `track_position`). Μια θέση του Gazebo δεν πρέπει ποτέ να γίνει
  αναφορά για τον πραγματικό βραχίονα.
- Υπηρεσία `/arm_logbook/last_position` (Trigger, JSON) για την εκκίνηση του υλικού.
- **Εκκίνηση (συμπληρώνει το ADR-0019):** η πρώτη ένδειξη κάθε encoder δίνει πιθανές θέσεις που απέχουν 360°
  (π.χ. −179° ή 181°). Επιλέγεται όποια είναι **πιο κοντά στην αποθηκευμένη**. Αν καμία δεν είναι κοντά
  (αρχική τιμή: 10°, προς επαλήθευση), η άρθρωση άλλαξε θέση όσο ήταν σβηστή: **δεν οπλίζει** και ζητείται
  calibration για αυτήν.
- Δουλεύει επειδή ο βραχίονας δεν κινείται με το χέρι όσο είναι σβηστός. Το μηχανικό τερματικό μένει δεύτερη γραμμή.

### 3. Καταγραφή: διακόπτης «● REC» στο Arm Studio
- Ενεργός μόνο όσο τρέχει το σύστημα. Ζητά σημείωση και τρέχει `ros2 bag record` στο
  `$ARM_DATA_DIR/recordings/<ημερομηνία_ώρα>/` για τα `/joint_states`, `/tf`, `/tf_static`, `/robot_description`,
  `/diagnostics`, `/arm_controller/joint_trajectory`, `/arm_controller/controller_state`, `/clock`.
- Έναρξη και λήξη γράφονται στον πίνακα `recordings`. Σταματά μόνο του όταν σταματά το σύστημα.
- Για τη διπλωματική: η καταγραφή μένει στο `.local/` με αντίγραφο σε cloud· στο git μπαίνουν το επεξεργασμένο
  CSV, το script ανάλυσης και η σημείωση της μέτρησης.

### 4. Calibration ανά άρθρωση: λειτουργία (πάνελ) του Arm Studio
Για κάθε άρθρωση, μία-μία:
1. κίνηση με **ταχύτητα** (◀ / ▶ όσο είναι πατημένα, ρυθμιζόμενη ταχύτητα), χωρίς να χρειάζεται γνωστή θέση,
   με τα όρια ασφαλείας του `calibration.yaml` (`max_offset_us`, `max_duration_s`, `max_travel_deg`)·
2. live ένδειξη του encoder· έλεγχος φοράς (με ▶ η γωνία πρέπει να ανεβαίνει, αλλιώς ρυθμίζεται το `invert`)·
3. ο χρήστης φέρνει την άρθρωση σε **γνωστή γωνία** (όχι υποχρεωτικά 0, π.χ. 90° με αλφάδι), τη γράφει και πατά
   «Ορισμός»: `zero_deg = ένδειξη − πρόσημο · γωνία`· ✓ για την άρθρωση και εγγραφή στο `calibrations`·
4. η κανονική κίνηση μένει κλειδωμένη μέχρι να έχουν ✓ όλες οι αρθρώσεις και ο gripper.

Αντικαθιστά, όταν υλοποιηθεί, το «όλες μαζί στο 0» του ADR-0019 (`~/set_zero`).

### 5. Gripper
Μπαίνει στο ίδιο calibration. **Εκκρεμεί** από τον Φώτη: τύπος servo (θέσης ή συνεχούς περιστροφής), αν έχει
encoder ή διακόπτη, κανάλι PCA9685. Σε κάθε περίπτωση αποθηκεύονται τα όρια λειτουργίας του (π.χ. παλμοί
«ανοιχτό» / «κλειστό») και το λογισμικό δεν στέλνει **ποτέ** εντολή εκτός αυτών.

## Συνέπειες
- **Υπάρχουν:** `arm_logbook` (βάση + node, στο `bringup.launch.py`), «● REC», εγγραφή των μηδενικών του
  `~/set_zero` στο ιστορικό. Tests εκτός ROS· **αδοκίμαστα στο Docker**.
- **Δεν υπάρχουν ακόμα:** το πάνελ Calibration (θέλει εντολή κίνησης με ταχύτητα προς το υλικό, που ορίζεται μαζί
  με το `arm_hardware` / firmware), η επιλογή στροφής στην εκκίνηση (υλικό), ο gripper.
- Η βάση δεν μπαίνει στο git και δεν έχει αντίγραφο ασφαλείας από μόνη της· η τελευταία θέση ξαναφτιάχνεται με
  calibration αν χαθεί.
