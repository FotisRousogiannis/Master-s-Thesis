# Δοκιμή του `arm_pi_driver` με την πραγματική βάση

Σκοπός: η πρώτη κίνηση του βραχίονα από το node ROS 2 του Pi (ADR-0021), όχι από το `teleop.py`. Μόνο η βάση
(διαφορικό joint_1 yaw + joint_2 roll). Κάθε φάση στηρίζεται στην προηγούμενη· **αν μια φάση αποτύχει, σταματάμε**.
Συμπληρώνεις τον πίνακα «Αποτελέσματα» στο τέλος (και ό,τι παράξενο δεις στα «Παρατηρήσεις»).

Σε προσομοίωση (`ARM_PI_FAKE=true`) όλα έχουν ελεγχθεί· **με υλικό τίποτα**.

## Ασφάλεια — πριν από οτιδήποτε
1. **E-stop ή διακόπτης στο ρεύμα των servo (7.4 V), στο χέρι**, σε όλες τις φάσεις με ρεύμα στα servo. Κόβει τα
   μοτέρ ακόμα κι αν το Pi «κολλήσει» ή κολλήσει το I²C (τότε το PCA9685 κρατά τον τελευταίο παλμό· το λογισμικό
   δεν μπορεί να το σταματήσει).
2. **Βαρύτητα:** στη στάση ασφαλείας ο driver σταματά τους παλμούς· τα servo συνεχούς περιστροφής **χωρίς παλμό
   δεν κρατούν**. Ο βραχίονας σε θέση όπου το joint_2 δεν τον τραβά η βαρύτητα, ή στήριγμα από κάτω.
3. Πρώτες κινήσεις **μικρές** (5–10°) γύρω από εκεί όπου είναι ήδη η βάση· κανείς στον χώρο κίνησης.
4. Τερματισμός πάντα με `docker compose down` (σβήνει τις εξόδους) ή E-stop· ποτέ βγάζοντας το ρεύμα του Pi ενώ
   κινείται.

Εντολές: στο **Pi** από το `~/Master-s-Thesis/software/pi/docker`· στο **PC** μέσα στο container του Arm Studio
(`docker exec -it robotic-arm-dev bash`). Γωνίες στα topics σε **ακτίνια** (`μοίρες × 0.01745`).

## Φάση 1 — Λογισμικό, χωρίς ρεύμα στα servo
Λογική (3.3 V) αναμμένη, **servo χωρίς ρεύμα**.
```bash
cd ~/Master-s-Thesis && git switch draft && git pull
cd software/pi/docker && docker compose up -d --build --force-recreate      # ΧΩΡΙΣ ARM_PI_FAKE
docker compose logs -f
```
Αναμένεται: `υλικό I²C · 50 Hz …`, `encoder joint_1: …`, `encoder joint_2: …`, `έξοδοι: χωρίς εντολή`.
- `NO_RESPONSE` σε encoder → λάθος κανάλι mux στο `config/base.yaml` ή καλώδιο· `docker compose exec pi i2cdetect -y 1`.
- `PCA9685 δεν απαντά` → κανάλι 0 του mux / τροφοδοσία λογικής του PCA.
- `TOO_WEAK` στο joint_1 (μαγνήτης mux2): αναμενόμενο σήμερα· μετρά, με επιφύλαξη.

## Φάση 2 — Ανάγνωση, χωρίς ρεύμα στα servo
**PC:**
```bash
ros2 topic hz /base/joint_states              # ~50 Hz; αν λιγότερο, το tick δεν χωράει στα 20 ms
ros2 topic echo /base/joint_states            # οι θέσεις σε ακτίνια
```
- Γύρνα **με το χέρι** τη βάση (yaw) και ανέβασε/κατέβασε (roll): οι θέσεις αλλάζουν, με σωστό πρόσημο
  (θετική φορά όπως στο `teleop.py` [6]).
- Στη θέση αναφοράς της βάσης (εκεί όπου έγινε το μηδέν στον πάγκο) οι θέσεις ≈ 0.
- Στο Arm Studio, πάνελ «Σύνδεση»: «ROS 2 στο Pi» πράσινο· πάνελ «Συσκευές»: `encoder/joint_1`, `encoder/joint_2`.
- Ξεκόλλησε προσωρινά ένα καλώδιο encoder (λογική αναμμένη, servo σβηστά): `NO_RESPONSE`, η άρθρωση λείπει από το
  `/base/joint_states`· ξανασύνδεσέ το: επιστρέφει χωρίς επανεκκίνηση.

## Φάση 3 — Μικρές κινήσεις (ρεύμα στα servo, E-stop στο χέρι)
Διάβασε την τωρινή θέση (ακτίνια):
```bash
ros2 topic echo --once /base/joint_states
```
Στόχος = τωρινή θέση **+ 0.09 rad (≈ 5°)** στο joint_1, ίδια θέση στο joint_2. Παράδειγμα με θέσεις 0.10 και −0.05:
```bash
ros2 topic pub -r 10 /base/joint_commands sensor_msgs/msg/JointState "{name: [joint_1, joint_2], position: [0.19, -0.05]}"
```
Αναμένεται: log `έξοδοι: κίνηση` → `έξοδοι: στον στόχο`· η βάση στρέφεται ~5° και σταματά· το joint_2 μένει.
Μετά, ίδια δοκιμή για το joint_2 (±5°). Σφάλμα τελικής θέσης → πίνακας (ανοχή 1°).

**Watchdog:** με κίνηση σε εξέλιξη (στόχος ±10°), `Ctrl+C` στο `pub` → μέσα σε 0.2 s `καμία εντολή … (watchdog)`
και τα servo σταματούν.

**Μόνο το ένα:** εντολή μόνο για `joint_1` (`name: [joint_1]`): το joint_2 μένει εκεί που είναι.

**Όρια:** στόχος 3.0 rad (172°) στο joint_1 → κόβεται στο άνω όριο (50°)· η βάση σταματά εκεί, όχι πέρα.

## Φάση 4 — Μεγαλύτερες κινήσεις και μέτρηση (για τη διπλωματική)
- Βήματα 20°, 40° σε κάθε άρθρωση, με καταγραφή: `ros2 bag record /base/joint_states /base/joint_commands
  /diagnostics -o ~/bags/base_step_20deg` (ή το «● REC» του Arm Studio). Από αυτά: χρόνος ανόδου, υπερακόντιση,
  σφάλμα μόνιμης κατάστασης, σύζευξη της άλλης άρθρωσης (όπως το run5 του πάγκου).
- Επαναληψιμότητα: ίδιος στόχος 10 φορές από διαφορετικές αρχικές θέσεις· διασπορά του τελικού σφάλματος.
- Ρύθμιση PID (`config/base.yaml`, `law`): μόνο μετά από αυτές τις μετρήσεις, μία αλλαγή τη φορά.
