# ADR-0017: Ρυθμίσεις βαθμονόμησης — ένα αρχείο YAML, παράμετροι ROS 2, αλλαγή από το GUI

- **Κατάσταση:** Αποδεκτή
- **Ημερομηνία:** 2026-11-09

## Πλαίσιο
Τιμές όπως το πλάτος παλμού των servo (νεκρό σημείο, ελάχιστο/μέγιστο), τα κανάλια του PCA9685,
η αναστροφή φοράς και τα όρια ασφαλείας αλλάζουν συχνά όσο ρυθμίζουμε τον βραχίονα. Σήμερα βρίσκονται
μέσα στον κώδικα των εργαλείων πάγκου. Ο φοιτητής θέλει να τις αλλάζει από την εφαρμογή ελέγχου,
χωρίς επεξεργασία κώδικα, και να μένουν στο αποθετήριο.

## Εναλλακτικές
1. **Σταθερές μέσα στον κώδικα** — κάθε αλλαγή θέλει επεξεργασία και επανεκκίνηση· ίδια τιμή σε πολλά σημεία.
2. **Ρυθμίσεις της εφαρμογής (QSettings)** — εύκολο, αλλά οι τιμές ζουν στον υπολογιστή του χρήστη, εκτός git,
   και δεν τις βλέπουν τα άλλα nodes.
3. **Ένα αρχείο YAML στο αποθετήριο, που το σερβίρει ένα node ως παραμέτρους ROS 2.**
4. **Αποθήκευση στο ESP32 (NVS)** — οι τιμές ταξιδεύουν με την πλακέτα, αλλά δεν φαίνονται στο git και
   χάνονται με αλλαγή πλακέτας.

## Απόφαση
Επιλογή 3.
- **Μία πηγή αλήθειας:** `software/ros2_ws/src/arm_calibration/config/calibration.yaml` (στο git).
- Το node **`/arm_calibration`** (package `arm_calibration`, Python) διαβάζει το αρχείο και δηλώνει κάθε τιμή ως
  **παράμετρο ROS 2** με περιγραφή και επιτρεπτό εύρος. Αλλαγές ελέγχονται πριν γίνουν δεκτές (π.χ. το νεκρό
  σημείο πρέπει να είναι μέσα στο εύρος παλμών). Υπηρεσίες `~/save` (γράφει τις τρέχουσες τιμές στο αρχείο) και
  `~/reload` (ξαναδιαβάζει το αρχείο).
- Το πάνελ **«Παράμετροι»** της εφαρμογής δουλεύει με **οποιοδήποτε** node (τυπικές υπηρεσίες παραμέτρων του
  ROS 2)· για το `/arm_calibration` δείχνει επιπλέον «Αποθήκευση στο αρχείο» και «Επαναφόρτωση από αρχείο».
  Το GUI μένει «λεπτό» (ADR-0016): δεν διαβάζει ούτε γράφει το αρχείο το ίδιο.
- Στο Docker το αρχείο δίνεται με τη μεταβλητή `ARM_CALIBRATION_FILE`, ώστε η αποθήκευση να γράφει στον φάκελο
  του αποθετηρίου και όχι στο αντίγραφο του `install/`.

## Αιτιολόγηση
Οι παράμετροι είναι ο τυπικός μηχανισμός του ROS 2: τις βλέπουν όλα τα εργαλεία (`ros2 param`, rqt), έχουν τύπο
και εύρος, και αλλάζουν ενώ το σύστημα τρέχει. Το αρχείο στο git δίνει ιστορικό: κάθε αλλαγή βαθμονόμησης είναι
commit, άρα ξέρουμε με ποιες τιμές έγινε κάθε μέτρηση της διπλωματικής.

## Συνέπειες
- Οι αρχικές τιμές του αρχείου προέρχονται από τον πάγκο καρπού (`docs/testing/wrist_bench.md`): 50 Hz,
  500–2500 µs, νεκρό σημείο 1600 µs, κανάλια 8–11. Δεν είναι τελικές.
- Όποιος χρειάζεται αυτές τις τιμές (`arm_hardware`, firmware μέσω micro-ROS, εργαλεία πάγκου) τις παίρνει από
  το `/arm_calibration` ή από το ίδιο αρχείο — **όχι** δικό του αντίγραφο. Αυτή η σύνδεση **δεν υπάρχει ακόμα**:
  σήμερα η αλλαγή μιας τιμής δεν φτάνει σε κανένα servo.
- Εδώ θα μπουν και οι μηδενικές θέσεις των encoders όταν αποφασιστεί η αρχικοποίηση των αρθρώσεων.
- Μια αλλαγή ισχύει αμέσως στο node αλλά μένει μόνο αν πατηθεί «Αποθήκευση στο αρχείο» και γίνει commit.
